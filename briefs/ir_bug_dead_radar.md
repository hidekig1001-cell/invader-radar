## 調べてほしいこと
1. **音と振動が鳴らない**: 1179（× だけの組ができた瞬間に dead の音）と 1182（その手で 250 ms・強さ 0.3 の振動）が、この盤の流れで鳴らない筋を探す。考えられる筋を全部挙げて、コードで当たり外れを決める。例:
   - 「音 OFF」のとき play_sfx だけでなく振動も止まる作りか（止まるなら、仕様として正しいか。振動は音と別に出すべきかはユーザーに聞く）。
   - 数字の岩（レーダー）を含む区域・列で、dead の決まり（Rules.dead_marks、main.gd の curr_dead・last_dead）が、岩のマスを数えたり外したりする所に食い違いが無いか（吹き出しは出ているのに音が鳴らない、の食い違い）。
   - 2 つの組が順にできたとき、2 つ目では last_dead が true のままで鳴らない作り（「× だけの組が 1 つも無い → ある」に変わった瞬間だけ鳴る）になっていないか。ユーザーは「2 つ目の組ができたときにも鳴る」と思っている見込みがある。
   - スワイプでまとめて × を付けた手、元に戻す・やり直す、面の読み直し（進み具合の再開）の手で鳴らない筋。
   - そのほか、Android の振動の許可・Sound の setup。
2. **数字の岩に宇宙人を置ける**: 左下 (0,4) の数字 1 の岩（レーダー）に宇宙人を置ける筋を探す。session.tap・double_tap・スワイプ・ヒント（apply_hint）・答え（ANSWER）のどれで置けるか。小惑星（数字の無い岩）では置けないのに、レーダーでは置ける違いがあるか（level.asteroids と level.radar の扱いの違い）。board の apply・Rules の判定・board_view の当たり判定を見る。
3. それぞれ、直し方の案と、ローカルの改修 run に渡す依頼の下書き（これまでの drafts/req_line_flash.txt と同じ形。決まりは「変えること」の箇条の中に書く。期待値は値まるごと。変わる既存のテストは main の実際のテスト名で書く。probe の .gd も書き、main の写しで直しを当てて通ること・直しなしで落ちることを確かめる。当て試しの直しは try_<名前>_patch.py）を書く。遊び心地の選び（例: 2 つ目の組でも鳴らすか、音 OFF でも振動するか）があれば、案を分けて、どれを推すかを書く。
