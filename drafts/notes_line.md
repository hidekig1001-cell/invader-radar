# 手触りの 2 本目「そろったら line の音と光」の調べ（10/27、main = v1.87-cr1178 / 05834fd）

前提: このあと InvaderRadar改修1179（dead の音と振動）、改修1180〜1182（振動の強さ。× を付けたとき 15 ms、宇宙人がぶつかったとき 250 ms、× が赤くなるとき 250 ms）が main に入る。この下書きは、それらが入った後の main を土台に書いた。

## 「そろった」の決まり（提案）

- 行・列・区域のうち、小惑星とレーダー（数字）のマスを除いたマスが全部「宇宙人」か「×」。宇宙人がちょうど 1 つで、その宇宙人が赤くない（`Rules.conflicts` に入らない）組。小惑星とレーダーのマスの除き方は `Rules.dead_marks` に合わせた。
- **答えと合うかは見ない、を提案する。** 理由は 3 つ:
  1. 答えと比べて鳴らすと、宇宙人の置き場所が正しいかどうかが、ヒントを使わずに分かってしまう。今は、まちがいを知らせるのはヒント（"THIS ALIEN IS IN THE WRONG PLACE"）だけで、ヒントは数に限りがある。
  2. 盤の答えは session の中に 1 つ持っていない（6×6 から上の面だけ `Solver.solutions(level, 1)` を使い、決まった面は答えを持たない）。答えと比べるには、毎手 Solver を回すことになる。
  3. 「赤くない」だけでも、宇宙人どうしがぶつかっている組（2 つ置いた行、赤い宇宙人の行）は鳴らない。
- 1 マスだけの区域（最初の面とチュートリアルの (3, 1)・(0, 2)）は、宇宙人を置くだけで「宇宙人 1 つで埋まりきった」ので、そろう。最初の面でそこに置くと line が鳴る（place の代わり）。
- 並びは、行（y の小さい順）→ 列（x の小さい順）→ 区域（番号の小さい順）。組は {"kind", "index", "cells"} の辞書。行と区域のマスが同じ（区域が 1 行ぶん）でも、別の組として 2 つ入る。

## 効果音の順（提案）

`level_clear > wrong > hint > dead > line > clear > place > mark`

- line は、新しくそろった組がある手で、sfx_for が clear・place・mark のどれかを返したときに替える。
  - clear: 赤い宇宙人を取って、ほかの宇宙人が赤くなくなった手。
  - place: 最後の空のマスに宇宙人を置いた手。
  - mark: 最後の空のマスに × を付けた手。
- **wrong とは同じ手にならない。** 赤い宇宙人のいる組はそろわない。ぶつかる宇宙人を置いた手では、その宇宙人の行・列・区域はどれもそろわない。
- **level_clear が先。** 最後の宇宙人で面をクリアすると、行・列・区域が一度にそろう。クリアの音と演出（clear_effect）があるので、line も光も出さない。
- **dead が先**（1179 の dead は mark の手を替える）。1 回の × で「行 0 がそろう」と「列 3 が × だけになる」が同時に起きることがある（音の項目 10）。まちがいの知らせを先にする。このときそろった行 0 は last_lines に入るので、あとで鳴らし直さない。
- hint はヒントのボタンの手で、盤は変わらない。
- **増えたときも鳴らす。** dead は「まちがいの知らせ」なので、空から空でなくなったときだけ鳴らす。line は「進んだごほうび」なので、新しい組がそろうたびに鳴らす（音の項目 3）。
- 除くもの:
  - チュートリアルの間。チュートリアルの盤は 1 マスの区域 (3, 1) に最初に置くので、入れると test_cr_1038 の place の音が line に替わる。CR-1179 の dead もチュートリアルを除いている。
  - 最初の _refresh（last_snapshot が空）。読み直した盤に、そろった組があると鳴ってしまうため。

## 振動との合わせ方（迷った点）

- line の手は効果音が mark・place ではない。そのため、1177 の宇宙人の 30 ms と 1180 の × の 15 ms の振動は出ない。依頼の中身に振動の指示が無いので、line に振動は足していない。
- その結果、**test_cr_1179::test_no_dead_on_row_with_alien の振動の期待値が変わる**（音の CR の「変わる既存のテスト」）。宇宙人がいる行 0 を × で埋める手が line になり、15 が 1 つ減る。
- 別の案: line の手でも元の手の振動（× なら 15、宇宙人なら 30）を出す、あるいは line に自分の振動（例 40 ms・0.6）を付ける。前の案なら test_cr_1179 は変わらないが、_refresh で「元の効果音」を覚えておく変数が要り、変えることが 1 行増える。ユーザーの Pixel での手触りを見てから、別の CR で決めるのがよい。

## 光の作り方

- CR-1169 の弾みと同じく、board_view の `pop_clock`（_process で delta を足す時計）で時間をはかる。
- `flash_lines(lines)` が光り始めの時間 `flash_start = pop_clock` と、光るマス `flash_cells` を覚える。`_draw` が `flash_alpha(pop_clock)`（0.5 から 0.3 秒で 0 まで直線）の白で、タイルの形を上から描く。
- テストから読めるように、光らせた組のマスの並びを `flashes` に順に足していく。
- 描く場所は、マスの中身（× と宇宙人）を描いたあと、チュートリアルの暗くする覆い（5.）とヒントの枠（6.）の前。覆いやヒントの枠を、光で消さないため。
- `_process` は、光っているあいだ（と、0 になる最後の 1 フレーム）だけ queue_redraw を呼ぶ。弾みと同じ書き方。
- 光るのは line を鳴らした手だけ。main.gd の `sound.play_sfx` のあとで、sfx_name が "line" なら `board_view.flash_lines(new_lines)` を呼ぶ（new_lines は音の CR で作る _refresh の中の変数）。

## 迷った点と提案

1. **3 本に分けた**: 規則と表示を分ける決まりのため（上）。音と光を 1 本にまとめると 5 行を越える。
2. **答えと合う組に限るか**: 限らない（赤くない宇宙人 1 つなら鳴らす）を提案。答えを知らせることになるため（上）。限りたい場合は、規則の CR で Solver の答えと比べる関数が別に要る。
3. **line の手の振動**: 足していない。× の 15 ms が line の手で消えるので、test_cr_1179 の 1 つが変わる。手触りとしては「line の手も元の振動を出す」もありうる（上）。
4. **dead と同じ手**: dead を先にした。そろった組は覚えるだけで、あとで鳴らし直さない。
5. **1 マスの区域**: 置くだけでそろって line が鳴る。最初の面（4×4 の 1 面）の (3, 1)・(0, 2) がそれにあたる。気になるなら「2 マス以上の組だけ」にする案もある（規則の CR の決まりを 1 文足す）。
6. **光の色と長さ**: 白・最初 0.5・0.3 秒。地の色が明るい区域（黄色など）では見えにくいかもしれない。Pixel で見て、色（例: 薄い黄色）や長さを直す。
7. **level_clear の手の光**: 光らせない（クリアの演出があるため）。
8. **テストの test_cr_1179**: 1179 の run が作る実際のテストは、draft/cr1179 の probe と関数の名前や並びが違うかもしれない。音の CR の「変わる既存のテスト」は、CR を作る前に実際のテストから書き写すこと。
9. **origin**: user_text はユーザーの言葉が手元に無いので、Invader Radar29 の依頼の題（「手触りの 2 本目: 行・列・色がそろったら line の音と光」）を入れた。said_at は依頼の時刻（10/27 03:1x）。decision は振動の段と同じ D-20261026-0622 にした。ユーザーの実際の言葉と決まりの番号があれば差し替える。
