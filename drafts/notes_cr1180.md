## 強さ（amplitude）は使える

- project.godot は `config/features=PackedStringArray("4.7", ...)`。run_tests.sh も Godot 4.7.x。
- このセッションで落とした Godot 4.7.2 の ClassDB で、`Input.vibrate_handheld` の引数を見た: `(duration_ms: int = 500, amplitude: float = -1.0)`。
- amplitude は 0〜1 の強さ。-1.0 は端末の決まりの強さ。Godot の文書では、強さが効くのは Android（API 26 から）と iOS だけ。Pixel は Android 8 より新しいので効く見込み。
- 強さが効かない端末でも、長さ（15・250 ms）の差は出る。

## 記録のしかた（CR-1180）

- `vibrate(ms: int, amplitude: float = -1.0) -> void`。強さを省いて呼べるので、今の `sound.vibrate(30)` と test_cr_1177 の `s.vibrate(30)` は書き換えずに動く。
- `vibrations` には今と同じく ms だけを足す（test_cr_1177・CR-1179 のテストが ms の並びを見ている）。強さは別の配列 `vibration_amplitudes` に、同じ順で足す（省いたときは -1.0）。
- 宇宙人を置いた手の 30 ms は強さを渡さない（-1.0）。ユーザーは「置いたときの振動」を 1 ok にしているので、強さを決めて変えない。

## どの手で、どう振動するか（4 つが全部入ったあと）

| 手 | 効果音（sfx_for の順） | 振動 |
|---|---|---|
| 面をクリアした | level_clear | なし |
| 宇宙人がぶつかった（conflicts が増えた） | wrong | 250 ms・0.3（CR-1181） |
| ヒントを使った | hint | なし |
| 宇宙人を取った | clear | なし |
| 宇宙人を置いた | place | 30 ms・-1.0（CR-1177） |
| × を付けて × だけの組が空から空でなくなった | dead（CR-1179） | 120 ms（CR-1179）→ 250 ms・0.3（CR-1182） |
| × を付けた（上のどれでもない） | mark | 15 ms・0.4（CR-1180） |
| × を消した | なし | なし |

- 1 手で鳴る効果音は 1 つなので、振動も 1 手で 1 回だけ。**dead の手は mark ではないので、× の 15 ms の振動は出ない**（dead の 120／250 ms だけ）。CR-1179 は `play_sfx` の前に sfx_name を "dead" に替えるので、CR-1180 の `if sfx_name == "mark"` とぶつからない。try の台本でも、両方を当てた形で確かめた（下の結果）。
- ぶつかる宇宙人を置いた手は wrong が place より前なので、30 ms は出ずに 250 ms だけ（CR-1181 の項目 1）。
- スワイプは 1 手なので、× をいくつ付けても 15 ms の振動は 1 回（CR-1180 の項目 4）。
- チュートリアルの盤の手も、宇宙人を置いたとき（CR-1177）と同じく振動する（CR-1180 の項目 5、CR-1181 の項目 3）。dead はチュートリアルでは鳴らない（CR-1179）。

## 迷った点

1. **CR-1180 と CR-1181 を分けるか**: 5 行に収まるのでまとめることもできる。改修28 の案の番号に合わせて分けた（上の「分け方」）。
2. **CR-1179 の前か後か**: 依頼は main の今の形（CR-1179 なし）で書いた。CR-1179 が先に入ると、CR-1180 の「変わる既存のテスト」に test_cr_1179 の表明が要る（上の一覧）。その表明は、CR-1179 の run が作るテストを見ないと一字一句は書けない。
3. **強さを記録する配列**: `vibrations` を [ms, amplitude] の組の並びにすると、test_cr_1177 と CR-1179 の期待値が全部変わる。なので別の配列 `vibration_amplitudes` にした。
4. **チュートリアルでも × で振動するか**: CR-1177 の宇宙人の振動がチュートリアルでも出るので、それに揃えた。止めたいなら `not is_tutorial()` を条件に足す（項目 5 が変わる）。
5. **数の比べ方**: 強さの期待値（0.4・0.3・-1.0）は float。GDScript の同じ書き方の数どうしなので `assert_eq` の配列の比べで一致する（probe で確かめた）。
6. **origin**: said_at は「2026-10-26 22:5x」と分までは分からないので、そのまま書いた。decision は CR-1177・CR-1179 と同じ D-20261026-0622、plan は振動の段に 2 つを足した名前にした。22:5x に新しい決まりがあれば直す。step の「CR 4〜6 つ目」は、CR-1176・1177・1179 に続けて数えた。
7. **15 ms は短すぎないか**: 端末によっては 15 ms で振動を感じにくい。Pixel の確かめで弱すぎたら、20 ms か強さ 0.5 に上げる。
8. **× のある盤から立ち上げたとき**: 最初の `_refresh` は `last_snapshot` が空なので、今のコードでも "mark"（宇宙人があれば "place"）を鳴らす。CR-1177 からは、宇宙人のある盤を読み直して立ち上げると 30 ms 振動する。CR-1180 からは、× だけの盤でも 15 ms 振動する。CR-1179 は dead だけをこの手で止めた。立ち上げで音と振動を出さないようにするには、`_refresh` で `last_snapshot` が空のときは効果音を鳴らさない、という別の CR を出すのがよい（今のテストでは test_cr_1033::test_main_music_setup などが最初の音を見ていないかを、その CR で確かめる）。
